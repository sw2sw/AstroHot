# Security reporting

[中文](SECURITY.md) | [English](SECURITY.en.md)

Confirm an available private security-reporting channel first. Use [GitHub private vulnerability reporting](https://github.com/sw2sw/AstroHot/security/advisories/new) if enabled. Otherwise, contact maintainers through an existing private channel, or ask only how to report privately without disclosing vulnerabilities, secrets, or exploit steps. This document does not claim that the feature has been independently verified or promise a security email address that has not been established.

Provide the affected version, deployment method, minimal reproduction and impact, with only shareable redacted evidence. Test only in an authorized isolated environment, not against production databases, real user data or paid services.

Do not put secrets, passwords, cookies, private addresses, full databases or exploitable details in public issues, discussions, PRs or Git history. Actual credential leaks require timely authorized revocation/rotation; deleting files or creating fresh history is not completed remediation.

Submit ordinary bugs through the repository's collaboration channels. No long-term-support branch or fixed response deadline is promised; maintainers determine remediation and disclosure scope from actual risk.
