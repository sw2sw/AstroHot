## 二、天文应用 astroApplication：判断这条材料是否把 AI 用于天文/天体物理研究（AI4A）。
- applies：true 仅当正文明确描述 AI 用于天文观测、巡天数据、天体物理理论或空间任务科学；false 当材料明确属于其他学科或与天文无关；null 当材料不足以判断。提到“科学”“宇宙”“物理”“空间”等泛词不构成天文应用。
- evidence：applies 为 true 时，只复制**直接陈述 AI 用于天文**的那句原文（≤600 字，本步不翻译）；找不到原文支持时给 null，applies 也随之不可信。applies 为 false 或 null 时 evidence 为 null。
- referent：applies 为 true 时，写出 AI 被应用到**哪个具体天文对象/设施/巡天/数据产物**（如“星系光谱样本”“JWST 观测”“某巡天影像目录”），必须逐字出现在 evidence 中（≤80 字）。测量方法词（光谱、测光、干涉仪等）不是天文对象，不能当 referent；applies 为 false 或 null 时 referent 为 null。
- 证据必须本身支持天文应用这一结论，逐字存在只是必要条件：与天文无关的物理结论（如标准模型格点定义）即使原文确有此句，也不是天文应用；把天文仅当背景或对照（如“不同于天文巡天，我们研究蛋白质折叠”）同样不是应用。这两种情况 applies 给 false 或 null，不写 true。
- domain 与 astroApplication 必须自洽：材料主要属生命科学、化学或材料科学时，不应同时声称 AI 用于天文；确有天文应用就应把 domain 归到天文与天体物理（或面向科研的通用方法与工具）。

## 三、资料范围 scope：只根据这篇资料自身判断，不能从候选报道反推。
- single：核心报道只有一个具体发生，或围绕该发生的一项研究、解读、科普。同一项研究的多个实验、多组数据属于 single。没有具体发生的单一科普或公告可以是 single，但 fact 为 null。
- composite：正文实质性报道多个可以各自成条的发生（多项独立研究、多个数据/工具发布）。共同的机构、日期或主题不能把它们变成一个发生；仅把其他工作用作背景、比较或例证，正文仍集中于一个核心发生，则不是 composite。
- unknown：材料不足以辨别范围。不要仅凭标题、篇幅或能否抽到 fact 判断。

## 四、事实 fact：抽取本条资料当前报道的那次发生，供事实归组使用：
title（≤30 字）、subject（做出动作的主体）、action（本次动作，如"发现/发布/证明/更新数据/上线"）、object（动作的具体对象，如某理论、某数据集、某模型、某方法）、occurredAt（原文明示的动作发生日期 YYYY-MM-DD，未知为 null）。
- 机构的研究、数据或工具进展以机构为 subject，即使消息由普通账号发布；个人观点或发言以发言者为话语权主体。composite 必须为 null；没有可确认事件的观点/科普/公告稿也可为 null。
fact 非 null 时还包含 evidence 与 conditions：
- evidence：只复制支持核心事实的一句原文（≤600 字，找不到为 null，本步不翻译）。
- conditions：最多 4 条决定结论适用范围的原文短句，每条只有 {"quote":"原文连续短句（≤400字）"}。不翻译、不概括、不省略中间、不加省略号；必须能在收到的原文/主帖里连续查到。没有明确条件才给 []。

输出前核对当前动作（优先于标题和宣传措辞）：标题里的引入性词语不能覆盖正文明确的先后关系；若正文说此前已公开、本文是分享或讲解，action 与 fact.title 必须写讲解；只有正文明确本次才首次公开，才写发布/发现/证明。没有明示本次动作的日期时 occurredAt 保持 null，不拿发布时间/抓取时间/被引用时间补。
