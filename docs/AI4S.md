## 安全启动与配置

AI4S 是与天文主站隔离的「AI 赋能科学」阅读栏目。升级需运行常规迁移流程（新增 `0071_ai4s_scope.sql`），参见[部署指南](DEPLOYMENT.md)。迁移为已有材料保留 `astro` 默认值，不重采集、不自动重新分析。

初次启动继续保持 `COLLECT_ENABLED=false`、`MODEL_CALLS_ENABLED=false` 和推送关闭。公开包新增的 `rss-ai4s-synthetic` **默认停用**，仅是 `example.invalid` 的自编配置示例，不是可用信源，也不包含私有运营的来源清单、接入日期或初始文章名单。部署者需先核查采集、存储、模型输入和公开展示的使用权限，再替换 feed 地址、分类、初次导入 URL 白名单和 UTC 时间边界。`first_party` 和 T1 只是示例元数据，不是第三方授权证明。

来源的 `config.contentScope="ai4s"` 将新材料送入 AI4S；省略或设为 `astro` 保持天文通路。示例只接受 `Science` 分类，摘要不冒充全文，图片、站内全文和分发全文均关闭。`_aihot.initialUrlAllowlist` 限定首次导入身份，`initialNotBefore` 保存后续新身份的原始发布日期下界；首次导入记作 backfill，后续无有效日期的新身份不接纳。这些字段不是网页展示开关。种子脚本不覆盖已有来源，修改文件不等于更新现有数据库来源。

`industry/selection.ts` 的 `ai4sAutoSelection` 保持 **false**：评分不代表自动精选；编辑可人工精选。启用来源与打开全局采集阀是独立动作，打开全局阀还会使其他已启用来源参与采集。模型分析需另行配置供应商和预算；本次本地移植未运行真实模型或采集服务。

## 阅读与证据

首页、侧栏和手机「更多」提供 `/ai4s`。诺贝尔奖仍从导航和更多页进入，公开包保留原有合成演示，不包含真实获奖内容。AI4S 读取已存储的公开投影，读者访问不会触发采集或模型调用。

栏目有全部动态、精选、学科筛选及 AI4A（天文应用）子集；精选先排天文应用，再按时间排序，其余按时间排序。每页 40 条，最多 50 页。卡片打开条目详情，原文入口在详情中；返回时恢复所打开卡片的焦点。检测到内容变化时提示更新，失败可重试，不把失败请求当成成功更新。

短摘要材料必须明确「未阅读全文」。只有足够支持判断的材料才评分；材料不足保持待评。评分不是科学真伪验证。AI4A 标记需要结构化步骤给出学科、天文对象与原文证据的一致性检查，该检查也不等同于科学核验。跨列刊登由编辑明确决定，不为同一材料创建第二份身份或重新分析。

API 为 `/api/site/ai4s`，支持 `tab=all|selected`、学科 `domain`（`astro` 表示 AI4A 子集）和从 1 开始的 `page`。页面空态不说明数据库或任务故障；先区分当前筛选无结果、来源未配置、尚未采集和未形成公开投影。接口成功不代表真实来源或付费模型已经验收。

## 合成样例与验证边界

`industry/ai4s-gold.example.jsonl`、`tests/fixtures/ai4s/synthetic-science-rss.xml` 和相关测试的短摘要均为自编合成材料，不是真实机构发布或真实 feed 摘录。样例保留短摘要待评、研究/营销区分、学科归属与天文证据边界的测试含义。`scripts/eval-selection.ts --scope ai4s` 是可调用模型的评估工具，不是无成本命令；先阅读[评分方法](SCORING.md)，仅在独立测试库与本地假模型或明确预算授权下执行。

本地候选已执行离线 Web 构建、Web 测试和类型检查；未启动服务，未运行数据库集成测试、浏览器验收或 GitHub Actions。发布前需独立数据库验收迁移、采集边界、队列、跨列与回滚。既有[已知问题](../KNOWN-ISSUES.md)仍适用。

## 回滚

不要直接删除新增列或仅回退读取代码：这会丢失栏目隔离或使既有 AI4S 投影被旧代码当成普通天文材料。先关闭相关来源和任务，由编辑将 AI4S 公开内容撤回并重新发布投影，确认公开出口、刊报位置与移除记录，再考虑回退代码；保留新增列和原始材料。恢复时重新发布。以上是操作边界说明，本次未对数据库实施回滚。
