# 后台设置与日常管理

[中文](ADMIN.md) | [English](ADMIN.en.md)

> 依据参考源码后台与接口整理。最终发行须逐项核对页面名称、功能开关和字段。本文不是已完成公开版浏览器验收的声明；新增错误记录界面仍按实际验收更新。

## 1. 登录与权限

后台入口为`/admin`。在服务端`.env`设置`ADMIN_PASSWORD`和独立`SESSION_SECRET`，通过正式登录取得会话；不要在生产使用`DEV_AUTH_ROLE`开发旁路。可选飞书身份登录只在最终包确实包含且配置了相应应用/管理员名单时启用。

密码、管理员名单或会话密钥变更后，重启所有API进程加载同一份配置，再确认新登录与旧会话撤权。不要将密钥放到Web客户端或反馈截图。

## 2. 哪些在后台改，哪些在文件里改

| 设置 | 入口或配置 | 生效/核对方法 |
|---|---|---|
| 来源新增、启停、采集间隔、分级及参与方式 | 后台“信源” | 保存后重新打开该来源读回；再查实际运行结果 |
| 付费请求上限 | “设置 → 付费请求上限” | 分服务设置分钟/小时/日上限并读回；参考实现0为立即停用该服务 |
| 模型使用情况与支持的模型切换 | “模型与评测” | 看各步骤回执和token；切换范围以该页面实际支持为准 |
| 模型供应商URL、密钥、默认模型 | 服务端`.env`的`LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` | 重新加载相关进程；用有界验证确认，可能收费 |
| 内容可见性、字段修正、重新处理与归组 | “内容” | 操作后核对记录与公开页面；重处理可能收费 |
| 定时任务结果、失败队列与回执诊断 | “运行” | 同时核对任务状态和文章状态，不以队列完成代替发布完成 |
| 联系二维码及已有通知目标开关 | “设置” | 用自有素材，核对保存和实际显示；通知目标凭据仍在服务端配置 |
| 站名、说明、分类、主题与评分策略 | `industry/site.ts`、`taxonomy.ts`、`topics.json`、`selection.ts`、`prompts/` | 按构建/加载方式更新，核对页面及实际分析路径 |
| 站点公网地址、数据库与安全阀 | `.env`与容器环境 | 按[部署说明](DEPLOYMENT.md)重新加载，不能只编辑文件 |

不把表中服务端文件设置误写成“后台可编辑所有参数”。未公开/未验收的功能不可据此承诺。

## 3. 添加或调整来源

1. 在“信源”新建来源，选实际支持的RSS、网页列表、JSON列表或外部导入类型；第三方付费采集适配不是默认免费功能。
2. 填来源名称、稳定ID、入口和必要选择器，设置分级及参与方式。`editorial`参与阅读，`hot_signal`仅作为热度证据，`isolated`不进入公开页面；具体可选项按发行版核对。
3. 设置采集间隔与有限首次条数，默认保持停用。详见[来源目录](SOURCES.md)和[频度](CADENCE.md)。
4. 在保存前/来源详情中使用已有预览功能。预览会真实访问来源，不是纯本地动作，也不能代替完整分析与展示验收。
5. 只有核对权限后才考虑全文、图片或再分发；`site_fulltext`只控制全文公开，不是采集或AI输入总开关。
6. 有界试跑，检查原标题/原日期/URL、去重、材料范围、回执和公开展示，健康后再开启定时。

`industry/sources.json`是初始化种子，不是正在运行的来源数据库：参考seed只补缺失来源，不覆盖既有记录；从文件删除来源也不等于从库删除。运营调整用后台，保存后读回。

## 4. 模型、评分与预算

先配供应商和预算，再允许`MODEL_CALLS_ENABLED`；接入OpenAI兼容接口并不保证所有供应商都兼容实际请求/响应。保留原回执和锁边界，未知请求不得为了赶进度直接释放重试。

并发上限、请求间隔与供应商限额共同决定吞吐，按实际服务限额保守设置。积压、`no model slot free within ...ms`、429 与隔离令牌的处理见[模型服务容量与处理积压](../KNOWN-ISSUES.md#模型服务容量与处理积压)。

评分提示词与门槛修改应一起核对，参见[评分说明](SCORING.md)。切换模型或改提示词不应自动重分析全部历史内容；若需校准，明确样本、次数及预算后执行。

## 5. 故障查看与人工操作

先看“信源”单源健康和“运行”任务结果，再看“内容”该篇处理链，最后看“审计”人工变更。普通无新增、相关性BLOCK或未进精选不算系统故障。

“立即抓取”、重排失败文章、重新分析、重新归组、回执释放、通知重新投递都是有副作用的操作，不应当作查看按钮。先确认失败原因、锁/回执与预算，再针对明确范围处理；不能把未知付费调用自动认作失败。

## 6. 反馈与私有材料

已有“反馈”用于管理读者反馈；反馈截图、失败来源响应和模型原答复属于私有证据，不作为静态目录对外公开。导出问题时仅给合成/脱敏复现，保留必要状态和版本，不贴真实密钥、个人信息或数据库连接串。

自动错误记录仍以[错误记录说明](ERROR-RECORDING.md)的实际实现/验收状态为准，不冒充已可用的自动修复系统。
