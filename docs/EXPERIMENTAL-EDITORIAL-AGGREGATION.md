# 轻量天文信息汇总：实验分支说明

> Experimental lightweight astronomy information aggregation. This is an alternative editorial workflow, not a production-equivalent optimization or a validated deployment release.

分支：`experiment/editorial-cost-reduction`。

本分支整合 [PR #8](https://github.com/sw2sw/AstroHot/pull/8) 的信源降噪、[PR #9](https://github.com/sw2sw/AstroHot/pull/9) 的标题合批及候选二轮复核，并包含调度VM测试兼容修复。原PR分支保留追溯，未合并到 `main`。

## 定位与分支选择

| 分支 | 定位 | 使用建议 |
|---|---|---|
| `main` | 综合天文资讯、论文初筛与双语阅读平台，维护完整的分析、评分精选、事件归组及相关网站功能 | 默认维护与生产发布候选；部署应选择经过本部署环境验收的固定版本，而不是把分支名视为验收证明 |
| `experiment/editorial-cost-reduction` | 轻量天文信息汇总：来源降噪、标题合批、来源导语及原文链接、少量候选的官方材料复核 | 实验评估用途；仍有下列阻塞项，不是当前推荐的生产部署分支 |
| 原PR和历史过程分支 | 开发、审查或历史修复记录 | 不作为独立的生产版本目录；已合并且无后续用途的过程分支可另行清理 |

这是同一框架下不同的编辑处理路线，**并非已拆成独立产品**。分支仍保留论文、影像和专题等框架代码，不会因使用该分支就自动关闭其他模块。

## 与综合网站默认流程的差别

| 环节 | 默认综合流程 | 本实验方案 |
|---|---|---|
| 内容覆盖 | 宽召回，实质天文/任务内容进入后续处理 | 更强调天文主旨，提前排除部分栏目、器材评测、普通商业航天与综合简报 |
| RSS/新闻列表采集 | 来源间隔与既有调度 | 未修改采集间隔；降低的是无关入库及后续处理，不是降低列表轮询频率 |
| 普通稿 | 按需取正文，逐篇预筛、评分、结构化及理解/摘要，再归组 | 标题合批判断相关性，沿用来源导语；无导语可只显示标题和原链接 |
| 精选 | 两次独立评分、按来源分级门槛判断，并经过身份/价值归组 | 每轮最多提出两篇候选，后续轮次基于官方公告或论文摘要复核，由预筛能力绑定的模型给出select/keep/duplicate |
| 处理节奏 | 入库后按队列与扫尾推进 | 北京时间08:00、13:00、20:00，每轮最多32条新标题及两篇既有候选；多余内容等下一轮 |
| 事件与重复 | 原事实/事件归组链路 | 新普通稿不入原逐篇归组任务，使用本批sameAs提示及近期精选/证据URL去重 |
| 内容与图片理解 | 沿用内容理解及图片审核边界 | 不运行原内容理解链，不能宣称保留了其分析深度或首图审核结果 |

因此不能将本分支表述为“完全相同的质量、仅把旧调用合并”。它更适合低调用量的信息汇集与浏览；是否接受分析深度、精选策略和发布延迟的变化，应单独评估。

## 来源与启用边界

- Nature候选RSS改为天文与行星科学专题，按标题过滤Daily Briefing；Astronomy Magazine News按分类排除 `Telescopes and Equipment`、`Ask Astro`，New Scientist Space排除 `Military`。
- 分类黑名单在模型前执行。科学仪器进展若同时带被拒绝分类，后续提示词的科学仪器例外无法救回；需要真实、多分类样本评估。当前没有真实样本证明已经发生误过滤。
- `industry/sources.json` 只是种子。`scripts/seed.ts` 对已有ID执行 `ON CONFLICT DO NOTHING`；升级或重跑seed不会覆盖已有数据库来源。
- 来源变更应单独审核，以管理员审计及版本检查更新，保留启用状态、cursor、间隔、限额、转载许可和私有元数据。不要重置来源或自动导入历史内容。
- `NEWS_TITLE_BATCH_ENABLED` 默认关闭；新闻轮次需同时开启 `MODEL_CALLS_ENABLED`。arXiv保留独立采集与分析路径。
- 沿用预算、回执和模型容量准入。候选仍会检索官方材料，不能保证所有HTTP请求总量一定减少。
- 不包含任何真实凭据、私有模型选择、站点地址或运营内容。分支发布不等于部署或启用。

## 合并或用于生产前的阻塞项

### P1：未知付费结果恢复必须保留原批次身份

`jobs/content.ts` 捕获unknown后将文章标failed并正常返回。回执放行后只将文章恢复new；下一轮重新组合标题、候选材料及近期精选，变化会生成新的round hash、attemptTag与receipt。

相同未处理内容可能以新回执重复发送，并反复获得每个新回执的一次自动放行机会；普通失败重排也可能旁路原unknown阻断。全局供应商预算仍生效，但逻辑请求的未知结果恢复上限没有守住。

应持久绑定原round与receipt，恢复时使用原payload/身份；普通重排不得清除未放行unknown。应覆盖新增标题、材料变化、精选变化、第二次未知以及普通重排的回归测试。

### P2：候选稿手工重提取不能静默跳过

管理员重提取先将正文状态设pending并入队force=true；worker对 `title-selection:` 标签的提前返回却在force检查之前。API返回jobId且审计记录提交，但未真正提取。

应明确让手工force覆盖候选拦截，或在接受操作前明确拒绝，不应接受后无动作。

## 验证范围

已修复原arXiv调度测试的VM上下文缺少config问题：该测试剥离所有import后执行整个共享调度文件，新增新闻轮次引用config导致夹具报ReferenceError。这不等于已证明arXiv生产调度损坏。

修复没有改生产调度代码或跳过arXiv断言，增加了新闻两个开关的四种组合、北京时间轮次与回调检查，保留arXiv每分钟检查、独占队列及禁止队列重试的断言。定向命令：

```sh
node --test tests/arxiv-continuous-schedule.test.ts tests/arxiv-wiring.test.ts
```

该定向测试已通过8项；PR #9的修复提交 `63ebdf7d88be42506cc756d1813769af06ec1e3b` 也已在GitHub通过 `check` 和 `docker`（[运行记录](https://github.com/sw2sw/AstroHot/actions/runs/43607070269)）。这些结果不等于本整合分支已完成全部CI、真实模型质量、来源材料抓取及生产验收。来源过滤的真实模型召回也不能仅凭模拟模型或配置测试宣称通过。

采用前需先修复上述阻塞项，并用真实、可公开复现的代表性样本验证相关性召回、候选材料与主张匹配、同一事件去重、预算/unknown恢复及发布延迟。没有单独批准时，不切换默认流程、不迁移或重算历史内容。
